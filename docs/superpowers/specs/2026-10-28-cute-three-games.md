# 귀여운 바탕화면 장식과 세 게임

사용자 최신 요청: 관리 화면도 다른 화면과 통일, 게임 세 개 구성, 전체를 더 귀여운 장식처럼 표현. 원 대화(게임 기획 작성)를 다시 읽어 세 번째 게임이 회로 연결임을 확인했다. 현재 범위는 광산·정원·회로이며 던전은 구현하지 않는다.

## 표현

실사에 가까운 거친 픽셀 그림 대신 귀여운 작은 흑백 캐릭터 그림을 이미지 생성 도구로 제작한다. 광석과 화분은 둥글고 단순한 형태/작은 얼굴을 가진 장식 오브젝트, 회로는 작은 전구 친구들로 표현한다. 색은 흑백만, 투명 바탕과 조용한 모션 유지. 새 그림은 새 파일로 보존하고 이전 자산을 삭제하지 않는다.

게임 선택은 광산/정원/회로 세 개가 구별되는 그림으로 표시하고 이름은 툴팁과 접근성 레이블로 제공한다. 강화/판매/도감 같은 반복 조작부는 정리해 장식이 먼저 보이게 한다. 관리도 큰 불투명 사각 바탕 없이 작은 보관함 그림과 간결한 백업 동작으로 통일하되 오류·복원 확인은 읽을 수 있어야 한다. 280×380, 드래그/트레이, 컴팩트36px 유지. 추가 사용자 요청에 따라 접힌 막대도 투명하게 하고, 남은 글자 버튼은 채움·테두리 없이 글자만 표시한다. 배경화면 위 글자는 얇은 밝은 윤곽으로 읽을 수 있게 한다.

## 회로 연결

- 300개 고정 시드 퍼즐.1~150은4×4,151~300은5×5. 각 칸을 누르면 시계방향으로90도 회전하며 시작점의 전기가 모든 칸/전구에 닿고 모든 연결 끝이 맞으면 완료.
- 정답은 결정적 DFS 연결 트리에서 만들며 난수값과 회전 규칙을 버전1으로 고정한다. 생성 퍼즐이 이미 풀린 상태가 되지 않게 보장한다. 시간 제한/회전 비용/자동 진행은 없다.
- 회전 중 상태와 횟수,완료300기록,누적완료를 자동 저장한다. 다음 퍼즐과 현재 퍼즐 재시작,완료 퍼즐 재도전으로 기록을 개선한다. 중복 완료 방지. 실제 최단해 탐색 없이 최단 횟수/완벽 풀이를 보장한다고 표시하지 않는다.
- 초기 분량 목표는 하루약5개,300개이며 실제60일플레이를 검증했다고 주장하지 않는다.

## 저장 계약

AppState schemaVersion3. games={mine,garden,circuit}. 기존 두 게임 내용과 settings/revision/updatedAt은 보존한다. v1/v2 로드 시 원본을 pre-migration 스냅샷으로 먼저 보존하고 v3로 변환한다. 스냅샷 실패 시 원본을 건드리지 않는다. 백업 봉투는버전1유지. 이전 백업복원시 회로기록초기화 안내.

CircuitState={stage:1..300,rotations:number[16|25](0..3),turns:0..1000000,records:number[300](0..1000000),totalClears:0..1000000000000}. records는앞에서부터연속완료된양수기록뒤에0만허용. stage<=min(300,완료수+1). totalClears>=완료수. 초기stage1,turns0,records0,totalClears0,rotations는초기퍼즐스크램블(구현 후TS/Rust공통fixture로고정). TS/Rust는정확한키·범위·길이를동일검증.

검증: 300퍼즐정답가능/결정성,회전·완료·중복·재도전/저장경계,TS/Rust공통fixture,원본보존마이그레이션,세게임백업왕복,실제화면밝고어두운배경,Windows빌드/사용자확인.

초기 회로 배열은 `[3,2,0,2,0,2,1,1,3,2,1,1,3,1,3,0]`로 고정했다. 기존 v2 fixture는 마이그레이션 검증에 그대로 두고, 새 v3 fixture는 실제 reducer로150개를완료한후151번에서2회전한상태를 저장해 TS/Rust 양쪽에서 읽는다.
