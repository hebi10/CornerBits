# 세 게임과 귀여운 장식 구현 순서

1. 독립 회로 담당: circuit.ts/Circuit.tsx/circuit.css/circuit.test.ts. 스펙의 상태 계약과 생성 결정성을 고정하고 초기 배열을 네이티브 담당에게 전달한다.
2. 독립 네이티브 담당: src-tauri/src 저장/게임 검증 모듈과 Rust 테스트만. v3,정확한v1/v2→v3이전,원본스냅샷,TS와공통fixture.
3. 메인: 생성 그림,src/core/state와platform,App/style,통합E2E/fixture,관리 화면/3게임 선택,문서/버전/최종검증.
4. 별도 화면 담당은 기존 Mine/Garden JSX/CSS에서 조작부를 줄이고 귀여운 아틀라스를 소비하도록 수정한다. 게임 엔진 변경 금지.
5. 독립 리뷰,유의미한회귀·마이그레이션검증,Windows실행,사용자화면확인,로컬커밋. push/deploy/파괴적정리/Computer Use 없음.

진행: 구현과 독립 논리·시각 리뷰, 207개 단위/25개 브라우저/42개 Rust 검증, 정식 Windows 빌드를 완료했다. 실제 사용자 저장 v2→v3에서 두 게임과 설정/저장번호 보존 및 원본 스냅샷 동일성을 확인했다. 추가 요청한 투명 축소 막대와 글자 버튼을 반영하고 관련 브라우저 8개 검증 및 Windows 빌드를 다시 통과했다. 최종 실행파일을 열고 세 게임 기록 보존을 확인했다. 사용자에게 실제 축소/펼치기 화면 확인을 요청했으며, 네이티브 회로/백업 수동 확인은 아직 응답을 받지 못했다. 구현은 로컬 커밋으로 보존한다.
