# 2단계 실행 계획

Spec: ../specs/2026-10-28-phase-two-design.md

기존 브랜치/작업 폴더에서 작업하며 사용자 변경을 보존한다. 삭제·푸시·배포·새 의존성 없음. 병렬 담당은 파일을 분리하고 커밋은 메인 담당만 한다.

1. 광산 규칙과 화면: src/games/mine.ts, mine.test.ts, Mine.tsx, mine.css. 순수 행동 함수와 경계·경제·도감 테스트부터 구현.
2. 정원 규칙과 화면: src/games/garden.ts, garden.test.ts, Garden.tsx, garden.css. 시간 주입과 오프라인/역행/다중 수확 방지 테스트부터 구현.
3. 네이티브 저장: src-tauri/src/storage.rs 및 필요 모듈. v2 엄격 검증, v1 호환, 원본 변환 스냅샷, 실제 파일 왕복과 실패 보호 테스트.
4. 통합: src/core/state.ts, state.test.ts, platform.ts, App.tsx, style.css. v2 검증/변환, 게임 행동 자동 저장, 관리 화면 전환, 백업 요약, 깊은 복사.
5. 통합 검증: 기존 회귀 테스트 및 게임 진행/재실행/백업 왕복/잘못된 백업/오프라인 성장 E2E. 280×380 렌더링 확인, 리뷰, 필요한 수정, 전체 타입/단위/E2E/Rust 테스트와 Windows 빌드.
6. 문서·버전 갱신, 사용자에게 실제 창 확인 요청, 검증 근거 기록 후 로컬 커밋.

Review focus: v1 원본 손실, TS/Rust 스키마 불일치, 저장 중 연속 입력/복원 경합, 잘못된 게임 값, 시계 역행/긴 오프라인, 닫기 전 저장 실패, 소형 창 조작 가능성.

## 진행 기록

- 1~4 완료: 규칙·화면·v2 저장·v1 변환·통합 자동 저장 구현. v1 변환/깊은 복사 테스트 실패를 먼저 확인하고 보완했다. 광산/정원 규칙도 각각 미구현 실패 후 통과를 확인했다.
- 구현 판단: 정원 중간 품종은 초기36시간에서32시간으로 조정. 물주기 후24시간이 되어 하루1회 루틴의 전종 수확이71일에서59일로 줄었다. 하루2회는46일이며 실제 플레이 보장 기간은 아니다.
- 구현 판단: Windows의 mine.ts/Mine.tsx 및 garden.ts/Garden.tsx 대소문자 해석을 피하도록 컴포넌트 import에 .tsx를 명시하고 noEmit 전용 allowImportingTsExtensions를 사용한다.
- 5 완료: 단위147개, E2E13개, Rust31개 통과. TS/Rust 공통 fixture 왕복, 타입체크, 제품 빌드, Windows x64 실행파일 생성 성공. 코드 리뷰는 수정 필요한 기능 결함 없음. 선택적 밸런스 회귀 테스트 제안은 허용 일수 범위로 반영했다.
- 280×380 이미지4장 검토 및 독립 시각 검토 ship. 주요 조작과12화분 모두 표시, 도감/도움말은 세로 스크롤. 기존 흑백 디자인을 유지했다.
- 실제 v1 사용자 저장을 v2로 변환하여 설정 보존 및 원본 스냅샷 바이트 일치를 확인했다. 사용자 수동 게임/백업·복원 정상 확인, 실제 데이터와 복원 전 스냅샷 대조 완료. 네이티브 재실행은 새 화면 배치 요청에 따라 후속 검증으로 남겼다.
