# 바탕화면 위젯 실행 계획

Spec: ../specs/2026-10-28-desktop-widget-design.md

1. 네이티브: 독립 담당이 창순서 정책을 설계·테스트하고 Windows 도구 창 설정, 바탕화면 보기 및 포커스 변경 대응, 트레이 찾기 기능을 구현한다. 공개 Win32 API를 이용하며 Explorer를 조작하거나 외부 코드를 복사하지 않는다.
2. 프런트엔드: 메인이 최소화/항상 위 UI를 정리하고 위젯 상태 설명 및 투명 바탕을 기존 디자인에 맞춘다. 저장·게임 스키마는 유지한다.
3. 게임·저장 회귀, 위젯 정책, 타입/빌드/E2E를 확인하고 독립 리뷰한다. v0.1.1 Windows 실행파일을 빌드한다.
4. 사용자 직접 위젯배치/Win+D/다른앱/드래그/저장·재실행 확인 후 실제 파일을 대조한다. 검증 기록과 로컬 커밋. 푸시/배포 없음.

진행 근거:2단계 게임/저장 구현은6c6f47a에 보존되어 있다. 현재 열린 기존프로세스가 있어 실행파일 교체 전 종료 확인이 필요하다. Computer Use는 사용하지 않는다.

## 진행 기록

- 사용자 트레이 종료 후 기존 프로세스가 없음을 확인했다.
- 프런트엔드148개 단위테스트,14개 브라우저 테스트,타입체크·제품 빌드 통과. 오래된 alwaysOnTop 설정을 창 배치에 적용하지 않는 테스트 및 위젯 안내/컨트롤 테스트를 먼저 실패시킨 뒤 구현했다.
- 관리 화면은280×380에서 백업 버튼까지 표시된다. 최대12개 화분도 유지되며 가로 넘침과브라우저 런타임 오류가 없다.
- 독립 네이티브 리뷰에서 Tao의 window.show/상태 변경이 TOOLWINDOW 스타일을 덮어쓰는 문제를 발견했다. 초기설정 순서만 바꾸지 않고 WM_STYLECHANGING에서 도구창 불변식을 유지하도록 보완하며 실제own HWND 회귀테스트로 확인한다.
- HWND_BOTTOM 및 Win+D의 Explorer 동작은 실제사용자 확인 전 검증완료로 표시하지 않는다.
- 2026-10-28: 사용자 수동 확인 모두 정상 응답. 위젯배치 기능 완료. 이어서 사용자 요청으로 단색 이미지/동작을 추가하는 시각 개선 진행.
